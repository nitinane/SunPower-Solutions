# Frontend implementation checklist

Audit date: 2026-11-01. Contract captured by HTTP **GET /api/openapi.json** on the running local API (the application does not serve `/openapi.json`). [Exact OpenAPI snapshot](openapi-audit.json). Operation fields/statuses below come from that response; roles and business error codes come from the actual route dependency graph and reachable service functions, since OpenAPI does not describe those rules. The checked-in frontend screens are placeholders; checkboxes below are for the frontend teammate to answer.

## Global

- Base URL `/api/v1`; use `fetch(url, {credentials: "include"})` on all session requests. `sp_session` is HttpOnly; never read/store it in JavaScript. Use JSON bodies except multipart uploads.
- On 401 go to login and preserve the intended destination. On 403 show a no-access screen. A hidden/not-owned record may return 404. Use the endpoint role lists below; admin is automatically allowed by require_role.
- Error body: `{"error":{"code":"...","message":"...","fields":{"field":"reason"}}}`. `fields` is optional, with dotted keys for array fields. Show error.message and map fields inline. 422 is normally `validation_error`, not OpenAPI’s autogenerated HTTPValidationError shape. 409 may be lowercase `conflict` / `business_rule_violation` or a specific uppercase code. 413 shows upload-too-large; 429 asks the user to retry later; 500 may include request_id for support. Message-table placeholders such as {value} mean runtime details; display the actual server message.
- Money and Decimal hours/kW arrive as strings. Format rupees with en-IN grouping; keep calculations in decimal arithmetic or use server totals. Never do money arithmetic with binary floats. Send decimal input as strings.
- Timestamp responses are UTC; show in Asia/Kolkata (IST). Date-only values remain business dates. Send timezone-aware survey/delivery/payment timestamps. Week begins Monday IST.
- Page responses: `{items, total, page, page_size}`. Page starts at 1; page_size <=100; use operation defaults. Packages, users and support search return arrays, not Page. Dashboard blocks are not paginated (profit list max 50).
- Role → home: office → sales inbox; manager → crew calendar; technician → my day; warehouse → pick list; support → search; director → dashboard; surveyor → own surveys; admin → a role-accessible overview. These are frontend navigation recommendations, not additional backend routes.
- Demo logins by role only: director (1), manager (1), office (1), warehouse (1), technician (3), support (1). Password: see DEMO_PASSWORD. Surveyor/admin are supported roles but not demo-role logins.
- Every screen must implement loading (skeleton/progress), empty (explain next action), error (server message + safe retry preserving input), success (render returned state and refresh linked lists). Disable submit while pending; retain Idempotency-Key for retries of the same enquiry/payment. Use operation-specific state gates below and handle server rejection even after UI validation.
- Technician and warehouse screens must work at 360px with touch targets, camera permission/error handling and typed serial fallback. Verify real phones; HTTP localhost camera behavior does not prove HTTPS deployment.
